# StudyPath AI 多智能体升级实施提示词

请你作为资深产品架构师、教育科技专家和全栈工程师，在当前“智学研途 AI 个性化学习平台（StudyPath AI）”基础上实施多智能体升级。以下要求是完整任务边界，请先阅读项目代码、README、后端接口、数据模型、迁移脚本和现有测试，再制订分阶段方案并直接在新副本中实现。

## 一、工作区与原项目保护

1. 原项目是唯一基线，必须保持原目录中的源代码、配置、文档和运行数据不被修改。先将项目复制到一个新目录，例如 `StudyPath-AI-MultiAgent`，然后只在副本内开发；完成后明确报告原目录和副本目录。
2. 复制时保留源代码、必要配置模板、文档、静态资源和数据库迁移历史；不要把 `node_modules`、构建产物 `dist`、临时日志、缓存、测试数据库、上传的个人文件或向量库数据当作源码复制。保留 `.env.example`，实际 `.env`、API 密钥、签名密钥和用户数据必须安全隔离；如需本地开发密钥，仅在副本的本地忽略文件中以不回显、不提交的方式配置。
3. 绝不在终端输出、日志、报告、截图、前端代码、Git 历史或本提示词中写出任何密钥值。项目根目录 `.env` 中已经存在 `AGENTHARNESS_API` 配置项；只检查变量是否配置，不打印其值。DeepSeek 当前后端配置通过 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 管理，按项目现有服务端配置方式接入。
4. 新增配置必须有无密钥的示例和说明。所有 AI 密钥仅由后端读取；前端只调用本项目后端接口。

## 二、项目现状与技术约束

当前系统是 Vue 3、TypeScript、Vite 前端和 FastAPI、SQLAlchemy、SQLite/PostgreSQL 后端。已有账号体系、按账号隔离的课程资料库、PDF/DOCX/TXT/Markdown 文档解析、Qdrant 向量检索、FastEmbed 中文嵌入、Cross-Encoder 重排、证据阈值拒答、真实来源引用和 SSE 流式问答；课程、测验、错题、学习路径、知识图谱、学习计划等模块已有前后端基础。以现有 API、数据库迁移和页面为基础增量演进，不重写整站，不破坏现有登录、资料上传、引用定位、账号隔离和数据删除能力。

先区分真实功能、演示数据和尚未实现的功能。不得把静态页面、模拟响应或未接通按钮宣传成多智能体已落地。不得用 Mock 答案掩盖模型服务错误、资料检索失败或 AgentHarness 不可用。

## 三、要解决的社会痛点与产品目标

将产品定位为覆盖小学、初中、高中和大学阶段的个性化 AI 学习平台，解决以下具体问题，并在首页介绍、产品说明和演示流程中清晰呈现：

- 学习资料分散在课本、讲义、课件和个人笔记中，学生难以快速定位可信内容；通过个人资料库、检索增强问答和可追溯引用，让答案回到学生自己的课程材料。
- 大班教学和有限辅导时间难以照顾每个学生的基础差异；通过持续更新的学习画像、知识掌握记录和用户可调整的学习建议，帮助学生及时找到薄弱点。
- 错题只被收集、缺少原因分析和后续巩固；将错题关联到知识点与错误类型，提供讲解、间隔复习和同知识点变式练习，形成“发现—理解—练习—复测”的闭环。
- 学习计划容易流于统一模板或制定后被遗忘；根据目标、可用时间、掌握度、先修关系和复习状态生成建议，同时允许学生自主修改课程、顺序、时间和优先级。
- 教师或家长难以获得清晰、可操作的学习进展线索；以学习活动、掌握度变化和待复习知识为依据呈现摘要，不作超出数据依据的能力诊断或升学承诺。

产品不是替代教师，而是帮助学生获得随时可用、与资料相关、过程可解释的辅助学习支持。面向未成年人时，使用年龄适配的表述和默认设置；个人资料、学习记录和对话按账号隔离，遵循最小必要原则，并提供清晰的隐私说明和数据删除路径。

## 四、多智能体角色与协作方式

实现一个服务端调度智能体和四个领域智能体。智能体是有边界的服务组件，不要为“多智能体”而制造无意义的互相调用。

1. **用户画像分析智能体**：根据用户主动填写的学段、年级、学科目标、偏好、可用时间，以及经授权的课程进度、测验和错题记录，整理学习画像并提出下一步建议。输出依据、数据时间范围、置信程度和可调整项；没有数据时说明信息不足，不推测诊断。
2. **错题分析与举一反三智能体**：识别错题所关联的课程知识点和可能的错误类型，结合原题解析给出适合学段的讲解、复习建议和同知识点变式题。变式题须保留知识目标、标明其为新题，答案与解析需经过一致性检查；学生提交答案后再判定结果并更新记录，不得因模型生成题目而伪造掌握度。
3. **本地资料库智能问答智能体**：复用现有 RAG 检索、账号/知识库过滤、重排、证据门槛、引用编号、原文片段和流式输出。回答优先依据当前用户选定且已就绪的资料，引用资料名、章节/页码或片段；证据不足时明确说明并建议补充资料或改问，不可编造“资料中写明”。保留现有无证据拒答和失败关闭策略。
4. **知识图谱分析智能体**：基于真实课程目录、知识点及先修关系识别前置知识、后续学习方向和掌握度关联，解释推荐顺序。图谱中不存在的节点或关系不得由模型直接写入正式课程图谱；需维护时走管理员权限和审核流程。
5. **调度智能体（Orchestrator）**：判断用户意图、任务范围和学段，选择一个或多个合适的领域智能体；为每次调用提供最小必要上下文，支持串行/并行任务、超时、重试、降级、部分成功、结果合并和可追踪日志。最终答复需区分资料证据、账户记录和模型建议，避免重复调用和循环委派。高风险写入操作、学习计划变更、删除数据、管理员课程维护等必须由用户确认或通过现有权限控制。

定义统一的智能体输入/输出结构（任务 ID、用户 ID、学段、意图、证据、结果、引用、错误、耗时和状态），但不得把敏感资料发送给不必要的智能体。加入请求限流、超时与成本保护、提示注入防护、工具白名单、敏感信息脱敏和审计日志。日志不得记录 API 密钥或完整不必要的私人资料。

## 五、模型与 AgentHarness 接入规则

- DeepSeek 作为可配置的语言模型供应方，沿用后端 OpenAI 兼容客户端和现有 LLM 配置；模型名、Base URL 和能力须从配置/官方文档读取，不要硬编码模型名、假设所有型号支持相同工具调用能力，或更改现有 RAG 模型行为而不做评估。
- `AGENTHARNESS_API` 作为服务端凭证。先检查仓库中是否已有 AgentHarness SDK、地址、协议、账号/智能体标识和调用示例；如果没有，必须查明实际 AgentHarness 产品/API 的 Base URL、认证方式、请求格式、返回格式、流式协议及可用 Agent ID。不能仅凭 API key 猜接口，也不能把密钥发送给 DeepSeek 或其他第三方。
- 将 AgentHarness 集成封装为后端 Provider/Adapter，并与 DeepSeek 模型调用、业务调度逻辑解耦。若 AgentHarness 提供智能体运行时，则由其承担已确认的委派/工具执行能力；DeepSeek 作为配置的推理模型。若 AgentHarness 仅提供 API 凭证或其接口资料不足，先完成可配置适配器边界和明确的缺少配置说明，不得伪造“已接通”。
- 提供健康检查和可观测状态，只回报已配置/可连接/失败类别，不回显任何密钥。密钥只从服务端环境变量读取；不要通过浏览器、构建变量 `VITE_*`、请求 URL、错误堆栈或前端日志传递。

## 七、学段适配与交互要求

学生注册/个人资料增加可修改的学段、年级、学科和学习目标；字段校验与选项覆盖小学、初中、高中、大学，并允许其他学习阶段。学段应影响讲解词汇难度、例题复杂度、变式题难度、每日任务时长和界面文案，不改变知识事实。学生始终可以跳过、编辑或拒绝 AI 推荐，自己设置优先级和计划。

在现有页面上串联完整流程：登录与学段设置 → 首页学习概览 → 资料库上传和基于资料的问答 → 我的课程/目录/知识图谱 → 个性化学习路径 → 随堂检测 → 错题分析和变式复测 → 学习数据分析 → 自定义学习计划。每一步都要呈现加载、空数据、无证据、调用失败和成功状态，并标注推荐理由与来源。

## 八、交付步骤与验收标准

1. 先产出副本结构、现状功能清单、关键差距、数据流/架构图和实施计划，再按小步提交实现；所有改动仅发生在副本。
2. 新增后端智能体服务、Provider 接口、配置校验、API 路由、数据库迁移（仅确有需要时）、前端状态和交互。复用现有账号授权、RAG、学习活动、错题、课程图谱和学习计划接口，不重复造一套孤立数据模型。
3. 为调度路由、角色权限、用户隔离、证据引用、低证据拒答、超时/重试、模型不可用、AgentHarness 不可用、变式题答案校验和学段文案编写自动化测试。测试使用假 Provider/固定响应，禁止消耗真实密钥或向真实用户数据写入测试记录。
4. 运行现有和新增的前后端类型检查、构建与测试，修复由本次改动引入的问题。报告实际执行的命令与结果；未能执行的项目明确说明原因，不可声称通过。
5. 交付副本目录、架构说明、智能体职责与交互时序图、数据流与隐私边界、`.env.example`、本地启动说明、CodeArts 流水线配置/部署说明、测试报告、未完成的 AgentHarness 配置依赖清单及演示脚本。

验收时必须满足：原项目文件无改动；副本可独立启动；现有资料上传、RAG 引用、登录隔离、学习记录、课程、图谱、测验、错题和计划能力未回归；五个智能体角色有可验证的后端调用路径和失败状态；DeepSeek 与 AgentHarness 密钥只在服务端；CodeArts 负责研发交付流水线而非被误称为运行时智能体；系统能向小学到大学用户提供可解释、可人工调整、与真实数据对应的学习建议；任何未实现或依赖外部账号/云资源的功能均明确标注，绝不伪装成已完成。
