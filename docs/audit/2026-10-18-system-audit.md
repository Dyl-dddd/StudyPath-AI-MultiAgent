### 1.3 架构、优点与不足

结构：Vue SPA → API 门面 → 默认 Mock 适配器 → mock/data.ts；少量状态写 localStorage。真实 API 开关和 REST 路径只是前端占位。其余业务集中于约 56 KB 的 WorkspaceView.vue，聊天、图谱、上传、测验、统计、错题、计划和设置同处一个组件。

优点：README 对演示边界披露明确；Mock API 与 API 门面有初步隔离；TypeScript 领域类型存在；客观题评分按答案比对；Markdown-It 使用 html:false；图表有 ResizeObserver 清理和 dispose；本地原创 SVG 封面；响应式样式和 reduced-motion 样式已有基础。

不足：业务数据散落在组件常量；学习事件与统一数据模型缺失；跨页闭环断开；错误/加载处理不统一；部分按钮只提示、不执行对应动作。类型检查通过不等于功能或教育结论正确。

## 2. 严格问题清单

### P0：立即解决

本轮未发现可由代码证实的 P0 级隐私泄露、远程越权或密钥泄露。项目当前没有真实账户或资料服务；这不代表未来上线安全已验证。

### P1：参赛前必须解决或收窄宣称

#### P1-01：答疑不是 RAG，引用是预置内容

- 模块：答疑、资料库。
- 问题：Mock 仅按进程/线程、TCP、二叉搜索树、贪心等关键词返回固定答案；来源文档、章节、摘录和匹配分数均为预设值。上传不参与回答，聊天调用也未传 courseId。
- 位置：src/api/mock.ts:12；src/api/index.ts:11；src/views/WorkspaceView.vue:38,43-47,80-125,158。
- 依据：仓库无模型/embedding/vector store/PDF/DOCX 解析依赖或服务端。README 第 3、24、51、53 行声明无模型/检索/后端且上传未解析。
- 验证：查看 Mock 固定分支；任意文件只新增元数据，定时变失败；回答证据直接来自固定对象。
- 影响：若宣称真实 RAG，评委通过无答案、换课程、换文件追问即可验证失败；引用无法回到原文。
- 建议：当前叫“课程示例问答交互原型”，保留 Mock 提示。真实 RAG 至少包含解析、切分、检索、证据引用、生成、拒答和权限隔离。
- 工作量：演示边界说明半天；最小真实链路约 5–10 人日，另需内容标注与部署。
- 验收：引用有文档/章节/页码；上传资料能检索；无答案可拒答；引用回到原文；不同用户私有资料隔离测试通过。

#### P1-02：测验结果未更新错题和掌握状态

- 模块：测验、错题、图谱、路径、分析。
- 问题：客观题会正确按答案评分，但提交只写 studypath.lastScore。错题为固定数组，掌握率和路径还是另一组固定数字。
- 位置：WorkspaceView.vue:49-56,59-68,136-150；mock/data.ts:12-19,31-38。
- 依据：错题、图谱节点是组件/数据常量；提交唯一持久化调用是保存最后分数。
- 验证：用不同答题结果提交，只有当前分数变化；错题、图谱、路径不随练习改变。
- 影响：识别薄弱点并调整学习路线的核心教育闭环未实现，分析数字无法解释来源。
- 建议：先做可解释规则闭环：题目关联知识点 → 记录作答/时间 → 计算掌握投影和错误原因 → 调整路径 → 推荐资源 → 重测。
- 工作量：本地闭环 3–5 人日；含后端约 1–2 周。
- 验收：固定学生案例可展示“答错→识别薄弱点→路径调整→重测后更新”；刷新可复现且数字同源。

#### P1-03：课程图谱选择不换数据，关系没有语义类型

- 模块：图谱、学习路径。
- 问题：图谱选择器展示三门课，绘图/数量/详情始终读取全局数据结构图；摘要标题固定。边只有 source/target，没有先修或普通关联标记；先修关系另有独立硬编码映射。
- 位置：mock/data.ts:12-19；WorkspaceView.vue:22-32,128-129。
- 验证：切换课程后检查节点、数量和详情仍为同一组。
- 影响：多课程能力和先修逻辑无法验证，图上关系与路径可能矛盾。
- 建议：边增加 courseId、relationType、方向和来源；课程图谱独立；路径只消费审定过的 prerequisite DAG 并检测循环。
- 工作量：前端和数据结构 2–4 人日，课程内容校验另计。
- 验收：课程切换数据变化正确；关系类型与图例一致；先修环检测；节点关联资源/题目。

#### P1-04：推荐与路径没有读取当前学生行为

- 模块：首页、路径、学习画像。
- 问题：推荐文案和数组固定；路径步骤、掌握度、42%完成度、更新时间写在模板。课程 query 没用于生成路径。
- 位置：DashboardView.vue:19；DashboardV2View.vue:36-57,120-123；WorkspaceView.vue:136-138。
- 验证：改变课程、任务或答题后，推荐和路径内容不变。
- 影响：当前“个性化/自适应”是 UI 口径，不是基于学生数据的算法结果。
- 建议：先用可解释规则，并为推荐展示触发数据与生成时间；积累多次答题、题目难度和知识组件标注后再评估 BKT/认知诊断，不要为堆算法上 DKT。
- 工作量：规则型排序 3–5 人日；数据校准另计。
- 验收：推荐能指向具体练习/先修证据；不同学习轨迹产生可解释不同排序。

#### P1-05：关键异步失败没有一致错误态

- 模块：答疑、测验、首页、Store/API。
- 问题：sendQuestion、beginQuiz、首页加载、loadTasks 缺少统一 try/catch/loading-error 状态；关闭 Mock 会访问仓库未提供的服务端，失败可能造成永久 loading 或未捕获 rejection。

- 验证状态：未连接真实服务端；缺少异常恢复由控制流代码确认。
- 建议：统一错误态/重试；启动时显示 Mock 或真实环境；记录非敏感 request ID。
- 工作量：1–2 人日。
- 验收：断网、超时、4xx/5xx 后 loading 复位、有清楚提示且页面可继续使用。

## 3. 教育智能评估

### RAG

实际链路：上传（只存文件元数据）→ 解析（无）→ 切分（无）→ 向量化（无）→ 索引（无）→ 查询（关键词分支）→ 证据（预置摘录）→ 生成（无）→ 引用（模拟）。当前不构成 RAG。界面披露 Mock 是优点，但不改变实现程度。

评测集至少包含：库内直答、多文档综合、无答案、错误前提、恶意文档指令、不同用户资料隔离。指标必须报告样本量，不可凭空填值：

- Recall@K：每个查询相关证据中进入前 K 检索结果的比例，再对查询平均。
- MRR：每个查询首个相关结果排名的倒数，再对查询平均。
- 引用准确率：人工判定引用是否支持相应回答主张的比例，并定义计数单位。
- 忠实度/拒答准确率：分开人工标注证据支持与无证据时拒答，不用综合分掩盖失败。
- 延迟：按相同条件报告端到端 P50/P95。

### 知识图谱

有节点类型、掌握字段、详情抽屉、拖拽/缩放/筛选；当前数据结构课有 30 个手工节点、32 条手工边。没有边类型或证据来源，统一呈现为有向边；先修关系独立硬编码；课程选择器没有驱动多课程图。结论：静态课程关系图交互原型，不是能生成教学路线的图谱系统。普通关联可有环，生成拓扑顺序的先修边须审定且保证 DAG。

### 个性化与学习画像

构件包括本地任务、本地客观题评分、带静态 mastery 的节点。缺失统一学习事件、历史答题、题目与知识点映射、时长/资源采纳记录。画像不存在，推荐没有可核验的个体依据。先建规则型闭环，显示 reason codes 和证据；数据量足够后再校准 BKT/认知诊断。

### Agent 与教育价值

没有多智能体调度、工具、状态传递或执行日志。答疑主要为课程关键词 FAQ。页面有解释、示例、无证据提醒和简答题人工评阅提示；缺少按掌握程度分层、先问学生思路、错因诊断、迁移题验证。建议设计“提示→关键线索→完整解释”渐进帮助并记录学生作答。

| 分析 /analytics | 图表齐，但不是实际学习统计；切换日期和导出需真正工作或标预览。 |
| 错题 /mistakes | 固定列表，答题不生成错题；状态刷新不保留；重练应受知识点约束。 |
| 计划 /plan | 本地任务增改完成可用；日历、编辑、日期切换未实现；自由文本日期不适合正式日程。 |
| 设置 /settings | 主题可切换；保存姓名/学校等只提示。若提供保存按钮，需 Store 同步且刷新后保留。 |

## 6. 整改方案

### A. 最小改动（优先）

1. 每个 AI/路径/分析结果旁统一显示本地示例口径；README 已有总说明。0.5–1 人日。验收：演示不会让用户误认在线模型或真实检索。
2. 将导出、日历、编辑、资料保存等无行为控件明确标“预览”或补最小本地行为。1–2 人日。验收：可点击控件执行动作或明确不可用，不出现假成功。
3. 修复测验课程/知识点过滤，保存每次本地答题明细并由错题/分析读取同一数据源。2–4 人日。验收：换答案会改变记录，刷新保留。
4. 统一异步错误界面，新增 Chat/Quiz/Store 单测。1–2 人日。验收：拒绝请求后 loading 复位。

### B. 完整升级

需增加后端、鉴权、数据库、对象存储、解析队列、页码溯源、向量/混合索引、模型网关、审计日志、限流及删除策略。

建议实体：users、courses、materials、material_chunks、knowledge_nodes、knowledge_edges(relation_type/source)、questions(knowledge_node_ids)、attempts(user_id/question_id/response/correctness/created_at)、learning_events、recommendations(reason_codes/evidence_event_ids)、plans。服务端从认证身份确定 user/tenant scope，不能信客户端 userId。

接口：POST/GET materials 与 processing status；POST rag/query 返回 answer/evidence IDs/chunk/page/拒答原因；GET courses/:id/graph；POST attempts；GET learning-path、recommendations、analytics。密钥只放服务端密钥管理，不得放公开 VITE_* 变量。

约 3–6 周全栈小组可做单课程 MVP，取决于资料权限、部署和数据准备；不含教育效果实验。验收包括 API 合约、解析、RAG 标注集、租户隔离、失败重试、备份/删除和可复现部署。

### C. 创新方案：知识图谱约束问答与渐进式提示

- 动机：回答要引用本课程材料，也要顾及学生欠缺的先修概念。
- 方法：资料块保存 course/material/section/page/knowledgeNode；检索先做课程与权限过滤，再混合检索；加入先修节点证据；输出启发提示、关键步骤、完整解释三级。
- 实现：审定先修 DAG 和映射；建立人工证据问题集；接模型和检索；记录证据、提示级别、作答和重测。
- 基线：关键词 FAQ、普通课程 RAG、图约束 RAG + 渐进提示；固定同一模型/材料/问题集。
- 指标：Recall@5、MRR、引用准确率、忠实度、无答案拒答准确率、P95；教育侧提示采纳率、即时测验和延迟重测正确率。
- 风险：边标注成本、错误先修边导致漏检、提示服从不稳定、小样本不足以证明长期效果。未实验前不得声称显著优势。

1. **AUD-01 学习事件模型**：新增 learning types/store/API，记录 courseId、knowledgeNodeId、questionId、response、correctness、occurredAt、duration、source；先做 Mock adapter。
